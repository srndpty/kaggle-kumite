- 特徴量が完全一致する train 行の重複はない。全特徴量が 0 の行は train に 0 行、test に 1 行

### 注意: id は目的変数の順に並んでいる（リーク）

- train は Class_1 → Class_9 の順に並んでおり、Spearman(id, class) は 0.982

- そのため、id は特徴量から必ず除外する。CV の前には必ずシャッフルする（シャッフルなしの KFold だと fold ごとにクラス構成が偏る）

- 右に長い裾を持つ: 非ゼロ値の中央値は 1、99% 点は 22、99.9% 点は 51。歪度は最大 36.5（feat_30）

## 検証分割（P2）

- `src/cv.py` の `make_folds` を全実験で使う。`split_version = skf5-seed42`（StratifiedKFold、shuffle あり、5 fold、seed 42）
- 各 fold は 12,375〜12,376 行。fold 間のクラス比の差は最大 0.0001
- 分割を変えるときは `split_version` を変え、それより前の実験とは直接比較しない

## 仮説検証（P4）

比較は `dev compare 1 <基準> <run_id...>` で、同じ fold どうしの差（実験 − 基準、負なら改善）を見る。

### H1: log1p 変換

| 比較 | fold ごとの差 | 平均 | 改善 fold |
|---|---|---:|---:|
| E02 → E03（ロジスティック回帰） | -0.0077 -0.0055 -0.0096 -0.0111 +0.0033 | -0.0061 | 4/5 |
| E01 → E04（LightGBM） | -0.00001 0 0 0 +0.00001 | 0.0000 | — |

- 線形モデルでは改善したが、OOF 0.641 → 0.635 と幅は小さい。標準化だけでも裾の影響はある程度抑えられていたと考えられる
- LightGBM は best iteration まで E01 と同じで、差は浮動小数点の誤差の範囲。LightGBM は値の順序だけで分岐を作るので、単調変換は効かない（想定どおり）
- 線形モデル（0.635）は LightGBM（0.474）より大幅に悪い。特徴量間の相互作用が重要なデータと考えられる
- NN での効果は未検証

### H2: 誤差の内訳（E01 の OOF、`src/analyze.py E01`）

| クラス | 件数比 | 平均 logloss | 損失への寄与 | 寄与 / 件数比 |
|---|---:|---:|---:|---:|
| Class_1 | 3.1% | 1.352 | 8.9% | 2.85 |
| Class_2 | 26.1% | 0.403 | 22.1% | 0.85 |
| Class_3 | 12.9% | 0.898 | 24.5% | 1.89 |
| Class_4 | 4.3% | 1.306 | 12.0% | 2.75 |
| Class_5 | 4.4% | 0.141 | 1.3% | 0.30 |
| Class_6 | 22.8% | 0.176 | 8.5% | 0.37 |
| Class_7 | 4.6% | 0.963 | 9.3% | 2.03 |
| Class_8 | 13.7% | 0.240 | 6.9% | 0.51 |
| Class_9 | 8.0% | 0.380 | 6.4% | 0.80 |

- Class_2〜4 は件数 43.3% に対して損失の 58.6% を占める
- argmax での正解率は 82.1%。取り違えが多いのは Class_3 → 2（Class_3 の 42.7%）、Class_4 → 2（29.4%）、Class_1 → 9（18.1%）、Class_4 → 3（14.4%）、Class_1 → 8（12.4%）
- 取り違えは件数の多い Class_2 に引き寄せられる方向に偏る。Class_2 自体の損失は件数比より小さい
- 仮説で挙げなかった Class_1（→ 9・8）と Class_7 も、件数あたりの損失が大きい

### H3: 行集約特徴

- E01 → E05 の fold ごとの差は +0.0014 +0.0005 +0.0032 -0.0031 -0.0007（平均 +0.0003）。改善した fold と悪化した fold が混在しており、効果は認められない
- 木モデルは、特徴量の組み合わせからこの程度の情報をすでに取り出せていると考えられる

### H4: 温度スケーリング（`src/calibrate.py E01 E06`）

- E01 の OOF は過信気味だった。確信度 0.7〜0.8 のビンでは正解率 0.715 に対して平均確信度 0.750。ECE は 0.0151
- 温度 T は fold ごとに 1.098〜1.113（T > 1 は確率を穏やかにする方向）。他の fold の OOF で T を決めるクロスフィットなので、OOF スコアに検証データの情報は漏れていない
- E01 → E06 の fold ごとの差は -0.0011 -0.0038 -0.0020 -0.0034 -0.0020。5 fold すべてで改善し、平均 -0.0025
- 注意: テスト予測は 5 モデルの平均で、すでに確率が穏やかになっている（E01 の Late が CV より良い理由の候補）。単一モデルの OOF で決めた T をそのままかけると、テスト側では効きすぎる可能性がある。Late で確認が必要
