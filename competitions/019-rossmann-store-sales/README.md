## コンペ概要

**ドラッグストアの店舗ごとの日次売上を、店舗の属性・販促・祝日の予定から 48 日先まで予測するコンペ。**

- 主催: Rossmann（ドイツを中心に欧州で数千店舗を展開するドラッグストアチェーン）
- 背景（なぜこの予測が必要か）: 売上予測は各店長が個別に行っており、精度がばらついていた。信頼できる予測があれば、人員配置などの計画を立てやすくなる
- 予測するもの: 各店舗の各日の売上（`Sales`）
- 入力: 1 行 = 1 店舗 × 1 日。その日の営業有無・販促・祝日・学校休暇と、店舗の属性（種別・品揃え・競合店・継続販促）
- 開催期間・参加チーム数: 2015 年 9 月末〜2015 年 12 月 14 日（Leaderboard の最終提出日時の範囲）。`kaggle competitions leaderboard --download` で取得した Public Leaderboard は 3,300 行（2026-11-15 取得）
- 参考スコア（Public Leaderboard）: 1 位 0.08932、上位 10% 0.10293、中央値 0.11678

出典について: 主催者・背景は Kaggle Overview の説明文を記憶に基づいて要約したもの。期間・行数・スコアは取得した Public Leaderboard から確認した。

## 基本情報（P0 で記入）

- 評価指標: RMSPE（Root Mean Square Percentage Error、小さいほど良い）。売上 0 の行は採点されない（Evaluation ページの記憶に基づく。相対誤差は売上 0 で定義できない）
- 提出形式（File / Code / 推論API）: File。`Id` + `Sales` の CSV（41,088 行）
- Late Submission 可否: 可（2026-11-15 に「営業日の売上中央値 6,369、休業日は 0」を提出し、Public 0.43023 / Private 0.46228 が返ることを確認）
- 提出: `dev submit 19 <ファイル> -m <メッセージ>`、履歴とスコアは `dev submissions 19`
- データ概要: `train.csv`（店舗 × 日の売上・客数など）、`test.csv`（予測対象）、`store.csv`（店舗の属性）

### データの基本

- train 1,017,209 行: 2013-01-01 〜 2015-07-31（942 日）、1,115 店舗。欠損なし。(店舗, 日付) の重複なし
- test 41,088 行: 2015-08-01 〜 2015-09-17（**48 日**）、856 店舗（すべて train にある）。全店舗が 48 日ぶんそろう
- test は train の直後の期間で、時間的に重ならない。**未来を予測する問題**
- `store.csv` 1,115 行。欠損: 競合店までの距離 3、競合店の開店年月 354、継続販促（Promo2）の開始時期 544（Promo2 に参加していない 544 店舗と一致）
- train にだけある列: `Sales`（目的変数）と `Customers`（客数）

### 休業日と売上 0

- train の 17.0% が休業日（`Open = 0`）で、売上はすべて 0。営業日で売上 0 の行は 54 行だけ
- 日曜は 97.5% の行が休業
- test の `Open` は 11 行が欠損（店舗 622、2015-09-05 〜 09-17 の月〜土）。休業日は test の 14.6%

### 目的変数（売上 > 0 の 844,338 行）

- 中央値 6,369、1% 点 2,188、99% 点 17,789、最大 41,551
- 歪度は生の値で 1.59、log1p で -0.11
- 店舗ごとの売上中央値は 2,293 〜 21,872 と約 10 倍の幅がある。log1p 売上の分散の 57.1% は店舗間の差

### 曜日・販促・祝日

| 条件 | 売上の中央値 |
|---|---:|
| 販促なし / あり | 5,459 / 7,650 |
| 月曜 / 土曜 | 7,539 / 5,425 |
| 12 月 / 9 月 | 7,858 / 6,000 |

- 販促（`Promo`）は同じ日なら全店舗で同じ値。販促あり / なしの売上比は店舗によって 1.06 〜 2.09 倍と違う（中央値 1.38）

- 1 年前の同時期（2014-08-01 〜 09-17）に行があるのは 935 店舗

## 検証分割（P2）

`uv run python competitions/019-rossmann-store-sales/src/cv.py` で分割の診断を表示する。

### リーク経路

| 経路 | 対策 |
|---|---|
| `Customers`（test にない同じ日の実績） | 特徴量に使わない |
| 検証期間以降の売上から作った特徴（ラグ・店舗別統計） | 売上を使う特徴は、分割ごとに学習行（検証窓より前）だけから作る。`leak_check.py` で確認する |
| 同じ店舗の隣接日が学習と検証に分かれる（ランダム分割） | 主評価は時系列分割にする。ランダム分割との差は H2 で測る |
| 学習行の統計量に自分の売上が入る | 学習行の統計量は、日付順に 4 つに分けた期間ごとに、自分の期間以外から作る。入れた場合との差は E05 で測る |
| test の予定（`Open`・祝日）から作るカレンダー特徴 | 売上ではなく、提出時に分かっている入力なので使ってよい。ただし test の末尾ではそれより先の予定が分からない（検証窓にはこの打ち切りがない。未対策の差異） |

### 分割

- 学習・検証に使うのは売上 > 0 の 844,338 行（採点されない行は使わない。休業日は `Open` で分かるので、提出時に 0 にする）
- **主評価 `ts3-48d-teststores-v1`**: train の末尾から test と同じ 48 日の検証窓を 3 つとり、各窓を「窓の開始日より前の全行」で学習して検証する。検証するのは test に出る 856 店舗だけ

| 分割 | 学習 | 検証 |
|---|---|---|
| 0 | 〜 2015-03-09（711,668 行） | 2015-03-10 〜 04-26（33,580 行） |
| 1 | 〜 2015-04-26（755,389 行） | 2015-04-27 〜 06-13（32,930 行） |
| 2 | 〜 2015-06-13（798,454 行） | 2015-06-14 〜 07-31（35,262 行） |

- 検証されるのは 101,772 行。学習の末尾と検証窓の位置関係は、train と test の関係と同じ（直後の 48 日）
- **比較用 `random3-seed42-same-valid-rows-v1`**（H2）: 上と同じ 101,772 行をランダムに 3 つに分け、自分の検証行以外の全行（前後の日・未来を含む）で学習する。評価する行が同じなので、スコアの差がそのまま「補間できること」による楽観の大きさになる
- 分割が違う run は `dev compare` では比較できない（評価条件の不一致として拒否される）

## 仮説検証（P4）

比較は `dev compare 19 <基準> <run_id...>`（同じ分割どうしの差）と、`src/analyze.py compare`（店舗単位の bootstrap）で行う。

### H1: 目的変数の log1p

- E01 → E02 の分割ごとの差は -0.0065 -0.0161 -0.0054（平均 -0.0093、3/3 分割）
- 売上そのままの RMSE は売上の大きい店舗の誤差を重く見るが、RMSPE はどの店舗も同じ重みで相対誤差を見る。log にすると学習の目的が指標に近づく

## P5: 上位解法の調査

### 出典

- 1 位（Gert Jacobusse）: 本人の [Winning Model Documentation](https://storage.googleapis.com/kaggle-forum-message-attachments/102102/3454/Rossmann_nr1_doc.pdf)（2015 年 12 月、PDF 全 7 ページを読んだ）
- 3 位（Cheng Guo・Felix Berkhahn）: 本人の論文 [Entity Embeddings of Categorical Variables](https://arxiv.org/abs/1604.06737)（実験の節を読んだ。コンペの解法そのものではなく、特徴を 7 個に絞った比較実験の報告）
- 2 位は読んでいない

### 1 位解法の概要

- モデルは XGBoost のみ。労力は特徴量の作成と選択に集中した。目的変数は log、売上 0 の行は学習に使わない
- 検証は **train の最後の 6 週間の holdout**。特徴量の選択とアンサンブルの選択に使った。公開スクリプトのパラメータは Public Leaderboard で良かったが、自分の holdout では再現できなかったと書いている
- 特徴量の 3 原則:
  - recent data: 店舗ごと（さらに曜日・販促・祝日ごと）の直近の売上の要約。直近 3 か月・半年・1 年・2 年。各行について「前の月以前」のデータを使う。直近 1 か月だけの特徴は、6 週間先の予測には役立たないと考えて使わなかった
  - temporal information: イベントの前・後・最中の日数を表す「day counter」。販促の周期（14 日）、継続販促の周期、夏休み、店舗の改装、競合店の開店など。今週・先週・来週の祝日の数
  - current trends: 店舗ごとに、直近 3 か月・1 年の売上へ線形モデル（Ridge）を当てはめ、6 週間先へ外挿する
- 外部データ: 州ごとの天気（最高気温・降水量）。州の人口・所得や Google Trends は効かなかった
- アンサンブル: 特徴をランダムに選んだモデルを 500 以上作り、holdout で良かった組み合わせを選んだ。5〜9 月だけで学習したモデル、直近 1 か月を使わない「month ahead」モデルも加えた。test の 2 か月目（9 月）は month ahead モデルだけで予測した
- 統合は調和平均。全予測に係数 0.995 を掛けた（holdout と Public で最適だった値）。フォーラムで示された 0.985 を使っていれば Private はもっと良かった、と書いている
- 個々の XGBoost モデルでも Private は 0.105 前後

### 3 位の論文の概要

- 店舗・曜日・日・月・年・販促・州の 7 つをカテゴリ変数として埋め込み、全結合 2 層（1000・500）の NN で学習する。目的変数は log(Sales) / log(Sales の最大値)、5 つの NN の平均
- 特徴を絞った比較実験で、**データをシャッフルして分けた場合と、時間順に分けた場合の両方**を報告している（MAPE）。勾配ブースティングは 0.122（シャッフル）と 0.152（時間順）、NN は 0.070 と 0.101。埋め込みを入力にすると、時間順の勾配ブースティングは 0.115 になる

### 自分の取り組みとの差分

| 観点 | 上位解法 | 自分（P4 まで） |
|---|---|---|
| 検証 | 最後の 6 週間の holdout（1 位） | 48 日の窓 3 つ（うち最後が 1 位の holdout とほぼ同じ） |
| 目的変数 | log、売上 0 は除外 | 同じ（H1） |
| イベントまでの日数 | 販促周期・夏休み・改装・競合店なども | 休業日・祝日だけ（H4） |
| 直近の売上 | 3 か月〜2 年、曜日・販促・祝日ごと、ばらつきの指標も | 全期間の平均だけ（H3） |
| 予測期間の扱い | 直近 1 か月を使わない特徴・モデル。9 月は month ahead モデルだけ | 売上を使う特徴は学習期間の平均だけ。予測の遠さで作り分けていない |
| 傾向 | 店舗ごとの線形モデルで外挿 | なし |
| 外部データ | 天気、州 | なし |
| アンサンブル | 10 以上のモデル、調和平均、係数 | 単一モデル |
| モデル | XGBoost（1 位）、埋め込み NN（3 位） | LightGBM |

- ランダム分割が楽観的になること（H2）は、3 位の論文のシャッフルと時間順の差（0.122 と 0.152）でも確認できる
- 1 位も「Public で良かった公開スクリプトが holdout では再現できない」と書いており、時間順の holdout を信頼して進めている
