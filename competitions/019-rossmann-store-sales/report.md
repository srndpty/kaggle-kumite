# #019 Rossmann Store Sales 振り返り

1,115 店舗の日次売上を、店舗の属性・販促・祝日の予定から 48 日先まで予測する（評価は RMSPE）。詳細な数値と手順は [README.md](README.md) を参照。

## 結果

| run | 内容 | CV | Public | Private |
|---|---|---:|---:|---:|
| E00 | 店舗 × 曜日 × 販促の中央値 | 0.15822 | — | — |
| E01 | LightGBM（売上そのまま、提出は分割平均） | 0.13819 | 0.12326 | 0.13007 |
| E03 | log1p + 休業日・祝日までの日数（提出は分割平均） | 0.10621 | 0.14151 | 0.17311 |
| E06 | E03 の提出を、全行で学習し直した 1 モデルに変更 | 0.10621 | 0.11050 | 0.12624 |
| **E09** | **検証でも予定の打ち切りを再現し、分からない日数を上限 7 日で埋める（最終モデル）** | **0.10363** | **0.10867** | **0.12497** |

- E09 は CV の点推定で最良だが、E08（0.10391）との差 -0.0003 は bootstrap の 95% 区間が 0 をまたぎ、優劣は未確定
- CV は 3 つの検証窓で early stopping したモデルの評価で、提出（全行で学習し直した 1 モデル）の性能を直接推定した値ではない
- E09 は Public 1,197 / 3,300 相当（上位 36.3%、Late Submission の参考値）。Public の 1 位は 0.08932、上位 10% は 0.10293
- CV と Late の差: Public は +0.005、Private は +0.021
  - 説明できた範囲: 提出と同じ手順・同じ情報条件を train 内で再現した疑似テスト（最後の検証窓）では、学習し直したモデル 0.10881 が、early stopping した値（= CV の分割 2）0.11225 より良かった。この窓では early stopping による CV の楽観は見られず、CV と Late の差はこれでは説明できない
  - 切り分けられていない要因: Private は全提出で Public より悪い（ダミーの中央値予測でも +0.032）。分け方が分からず、原因は特定できていない。test は夏休みの時期で検証窓（3〜7 月）と季節が違うが、1 年前の同時期での検証は試していない

## 自力の仮説で効いたこと・効かなかったこと

効いたこと:

- **提出を、直前まで学習し直した 1 モデルにする**: 情報条件をそろえた疑似テストで、E09 は分割平均 0.1128 → 0.1088（-0.0040）。学習の末尾が予測期間から離れたモデルほど悪い（96 日前 0.117、48 日前 0.112）。#001 とは逆の向きだが、差は小さい
  - E03 では 0.176 → 0.120（Private 0.173 → 0.126）と大きかった。ただし主因は新しさではなく、分割ごとのモデルが「次の祝日が分からない（NaN）」行をほとんど学習していなかったこと（48 日前のモデルが 96 日前のモデルより悪い）
  - 当初の疑似テストは暦を切り詰めておらず、疑似テストの行が test 期間の予定まで見えていた（0.158 → 0.114 と記録していた）。レビューの指摘で修正した
- **休業日・祝日までの日数（E02 比 -0.0255）**: 休業日・祝日の前後 1 日は普段の約 1.21 倍売れる。P4 で最大の改善
- **目的変数の log1p（-0.0093）**: 相対誤差の指標に学習の目的を近づける
- **検証でも test と同じ「予定の打ち切り」を再現する**: 検証窓の行が窓より先の予定を見ていたため、E03 の CV（0.106）は楽観的だった。再現すると 0.130。分からない日数を上限で埋めて 0.104 に戻した

効かなかった・小さかったこと:

- **店舗別の売上統計量（学習行は自分の期間以外から作る方式で -0.0017、2/3 分割）**: この方式では学習行の統計量に自分より未来の売上が入り、検証行（過去の売上だけ）と作り方がそろわない。どの行も「その日より前の売上」だけから作ると（E12、レビュー後に追加）、E02 比 -0.0075、E04 比 -0.0057（bootstrap 95% 区間 [-0.0066, -0.0049]）。効果が小さかったのは作り方のせいだった。48 日前より前に限ると（E13）、E12 より +0.0014 悪い
- **学習行の統計量から自分の売上を除く（差 0.0003）**: 1 店舗あたり数百行の平均なので、1 行の影響は小さい。ただし E04 と E05 は時間的な参照集合も違うので、「自分の売上を含めることだけの効果」ではない
- **日数の上限を 30 日から 7 日に下げる（-0.0003）**: ノイズの範囲

検証分割について（今回のテーマ）:

- **ランダム分割は、同じ行を評価しても 0.025〜0.045 楽観的**（E02: 0.129 と 0.084）。この差には、未来の行を学習できること・学習行の多さ（約 81 万行と 71〜80 万行）・近い行からの補間がまとめて入っていて、内訳は分けていない
- **特徴量の採否が逆になる**: ランダム分割では、日数の特徴の効果が 1/8 に見え（-0.0029 と -0.0228）、店舗別統計量は有害に見え（+0.0051 と -0.0017）、自分の売上を含めた統計量が良く見える（-0.0042 と +0.0003）

## 上位解法から学び、再現したこと

出典は 1 位（Gert Jacobusse）本人の Winning Model Documentation と、3 位（Guo・Berkhahn）本人の論文。

- **直近の売上の統計量（E10、+0.0006、改善 1/3）**: 効果は認められなかった。ただし 4 列だけの再現で、1 位の作り方（曜日・販促・祝日ごと、ばらつきの指標、傾向の外挿、holdout での選択）とは規模が違う
- **予測に係数を掛ける（E11、+0.0006）**: 他の検証窓で決めた係数は悪化した。窓ごとの最適な係数が 1.009・0.994・0.984 とばらつく。3 窓全体での最適値 0.995 は、1 位が使った値と一致した
- 1 位も最後の 6 週間の holdout を信頼し、Public で良かった公開スクリプトを「holdout では再現できない」として採っていない。3 位の論文も、シャッフルした分割と時間順の分割で結果が大きく違うことを報告している（勾配ブースティングの MAPE 0.122 と 0.152）

## 上位解法との差分（試さなかった着眼点）

- イベントの種類: 販促の周期、夏休み、店舗の改装、競合店の開店までの日数
- 予測の遠さに合わせた作り分け: 直近 1 か月を使わない「month ahead」モデル、test の 2 か月目だけ別のモデル
- 店舗ごとの傾向の外挿（Ridge）、売上のばらつきの指標
- 外部データ（州ごとの天気、店舗の州の推定）
- 特徴をランダムに選んだ 500 以上のモデルからのアンサンブル選択、調和平均
- カテゴリ変数の埋め込みを使う NN（3 位）

## 既知の問題・未検証の事項

- Private が Public より一貫して悪い理由は分かっていない。次に試すなら、1 年前の同時期（学習 〜2014-07-31、検証 2014-08-01 〜 09-17、暦も 09-17 で打ち切る）の季節性 holdout。ただし 180 店舗はこの期間の行が無く、検証できる店舗が減る
- E12 の統計量と E09 の組み合わせは試していない（最終モデルは P7 の前に決めたので変えない）
- E07 の CV（0.130）は E06 の Late（Public 0.111）より悲観的だった。学習し直したモデルは train 末尾の「次の祝日が分からない行」も学習できるため、という解釈は未検証
- 検証窓は 3 つで互いに学習データが重なる。小さい差は店舗単位の bootstrap で確かめたが、同じ日の店舗間の相関は考慮していない。seed を変えた再実行はしていない
- 180 店舗の 2014 年後半の欠測を特別扱いしていない
- 売上が数日だけ普段の 1/3 以下に落ちる行（店舗 415 など）が誤差の大きな部分を占めるが、原因は分からない
- 学習し直しの round 数は「分割ごとの best iteration の平均」で、学習行が増えるぶんの調整はしていない
- E07 の記録の `changed_one_thing` に「テスト予測は E06 と同じ」とあるが、同じなのはテスト行の入力で、round 数が違うので予測は同じではない

## 次のコンペに持ち越すこと

- **時系列の問題では、検証を test と同じ条件にそろえる**: 学習の末尾と予測期間の距離、検証する対象（店舗）、**その時点で分かる情報の範囲（予定の打ち切り）**。特徴量を作るときに「この値は test でも同じように作れるか」を列ごとに確かめる
- **提出の作り方も検証する**: fold モデルの平均が良いとは限らない。train の中に疑似テストを取り置き、提出と同じ手順を再現して比べる（`refit_check.py`）。このとき、ラベルだけでなく入力（予定・暦など）も疑似テストの末尾で打ち切る。打ち切らないと、比べる方法の差を取り違える（E03 の差 0.18 → 0.12 を「新しさ」の効果と読み違えていた）
- **ラベルを使う特徴は、学習行でも「その日より前」の売上だけから作る**: 自分の期間以外から作る cross-fitting は外側の検証ラベルを守るが、時間の向きがそろわない。そろえると効果が 3 倍以上になった（H3c）
- **最初の提出は早めに出す**: E03 の CV と Late の食い違いから、打ち切りの問題に気づけた
- **共通化したもの**（`src/kumite`）: 明示的な分割でのクロスフィット（`crossfit.cross_fit_splits`、`split_roles`）、回帰の予測の検査と連続値の label perturbation（`checks.validate_regression`、`perturb_targets`）、CV 結果の採点と保存（`cv_run.publish_cv_run`）
- **共通化の候補**（次の時系列コンペで必要になったら移す）: 疑似テストでの提出手順の比較（`refit_check.py`）、グループ単位の bootstrap（`analyze.py`）、後処理を他の分割で決めて適用する枠組み（`scale.py`、#001 の `calibrate.py`）
- 追加・更新した知見カード: K001・K002・K004 に証跡を追記、K007〜K009 を追加
