# #024 Recruit Restaurant Visitor Forecasting 振り返り

日本の飲食店 821 店舗の日ごとの来店客数を、過去の来店数・予約・祝日から 39 日先まで予測する（評価は RMSLE。test は GW を含む）。詳細な数値と手順は [README.md](README.md) を参照。

## 結果

| run | 内容 | CV | Public | Private |
|---|---|---:|---:|---:|
| E00 | 店舗 × 曜日の中央値 | 0.56672 | — | — |
| E02 | LightGBM、log1p、店舗の属性 + 日付 | 0.54755 | — | — |
| E06 | E02 + 祝日・店舗別統計量・予約（提出は分割平均） | 0.52385 | 0.52628 | 0.55047 |
| E07 | E06 の提出を、全行で学習し直した 1 モデルに変更 | 0.52385 | 0.48231 | 0.51244 |
| **E09** | **E07 の曜日を、祝日を土曜とみなした曜日に置き換える（最終モデル）** | **0.52241** | **0.47984** | **0.50813** |

- 最終モデルは P6 の前に決めた規則（CV の点推定が最良で、E07 との差の bootstrap 95% 区間が 0 をまたがない）で E09 を選んだ。Late は選定に使っていない
- E09 は Public 554 / 2,150 相当（上位 25.8%、Late Submission の参考値）。Public の 1 位は 0.46535、上位 10% は 0.47800
- CV と Late の差: 学習し直した提出では Late の方が良い（E09 は CV 0.522、Private 0.508、Public 0.480）
  - 説明できた範囲: 時系列 CV で選んだ向き（log1p、3 種の特徴、学習し直し、E08 の不採用、E09 の採用）は、すべて Late の向きと一致した
  - 切り分けられていない要因: CV の窓 0 は年末年始を含んで RMSLE 0.545 と悪く（他の窓は 0.512）、test は年末年始を含まない。また CV は窓ごとのモデル、提出は全行で学習し直したモデルで、学習期間の長さが違う
- 分割平均の提出（E06）だけは Private 0.550 と CV より大きく悪い。CV と提出の作り方が違うと、CV は提出の性能を表さない

## 自力の仮説で効いたこと・効かなかったこと

効いたこと（どれも 3/3 分割で改善）:

- **目的変数の log1p（-0.0319）**: RMSLE は log1p 空間の RMSE そのもの。#019 の RMSPE（-0.0093）より 3 倍以上大きい。来店数そのままの LightGBM は統計的 baseline（中央値）より悪かった
- **店舗・店舗 × 曜日の過去の平均（-0.0138）**: どの行も「その日より前の学習行」だけから作る（#019 で効いた作り方）
- **祝日・前日休日・翌日休日（-0.0064）**: 改善の大半は年末年始を含む窓の 1 週目
- **予約（-0.0034）**: 予約の効果は小さく、改善は窓の 1〜2 週目に集中した。窓の開始前に入っている予約は、3 週目以降ではほとんど無い
- 3 つの組み合わせ（E06）は -0.0237 で、単独の効果の和とほぼ同じ
- **提出を、全行で学習し直した 1 モデルにする（Private -0.038）**: #019（疑似テストで -0.004）より 1 桁大きい。窓 0 のモデルが年末年始の窓で 48 round で止まって浅いこと、古いモデルが直近の来店数と新しい店舗を学習していないことが候補で、切り分けていない

情報の打ち切り（今回のテーマ）:

- **予約は、検証でも学習でも打ち切りを再現する必要があった**
  - 検証行で窓の開始以後の予約まで見せると、CV は 0.0049 楽観的になる（E05L）。test では再現しない改善
  - 学習行で来店日までの全予約を使うと（E05A）、予約を使わない E02 より悪い（E05 比 +0.0090）。学習時は予約がほぼ全部見えている行だけを学ぶので、予約がまだ入っていないだけの検証行を「来店が少ない」と読む（解釈）。学習行にも「何日先か」をランダムに割り当てて、予測時の打ち切りを近似的に再現すると（E05）改善した
  - E05A は「何日先か」の列（学習行はすべて 0）も同時に変えていた。この列だけ E05 に戻した E05B でも同じだけ悪く（E05A との差 +0.0004、区間 [-0.0004, +0.0013]）、悪化は予約の打ち切りの有無による（レビュー後に追加）

検証分割:

- **ランダム分割は、同じ行を評価しても 0.033〜0.040 楽観的**。#019 と同じ程度で、「隣の日との相関が弱いので楽観は小さい」という予想は外れた
- #019 と違い、特徴量の採否は逆にならなかった。ただし店舗別統計量の効果はランダム分割では半分以下に見えた（-0.0138 と -0.0065）

## 上位解法から学び、再現したこと

出典は、1 位の LightGBM の公開コード、8 位本人のノートブック、16 位本人の公開コード、上位解法を分析した論文（Bojer & Meldgaard、第三者の解説）。

- **祝日を土曜、休日の前日の平日を金曜、翌日の平日を月曜とみなす曜日（E09、-0.0014、bootstrap 95% 区間 [-0.0028, -0.0002]）**: 複数の上位者がコンペ後に効果を報告した変換。改善は祝日の行に集中した（0.651 → 0.628。それ以外は変わらない）。Late も Private -0.0043
- **学習行の統計量も起点に合わせる（E08、+0.0017、区間 [-0.0001, +0.0033]）**: 1 位は起点ごとに特徴を作り直した学習データを使う。学習行ごとに 1 つの起点を割り当てる近似で再現したが、悪化した。#019 の E13（予測期間ぶん離す）も悪化しており、ラベル由来の統計量は学習行では直前まで使う方が良かった。予約（打ち切らないと悪化）とは逆の結果で、違いは「打ち切りで値が系統的に偏るか」だと考えられる（未検証）
- 8 位は時系列を無視したランダムな 6-fold で検証して上位に入った。今回もランダム分割で採否は逆にならなかったので、矛盾しない

## 上位解法との差分（試さなかった着眼点）

- 1 位の学習データの作り方そのもの（起点を 7 日ずつずらして 58 個とり、行を複製して積み重ねる）。E08 は 1 行 1 起点の近似にすぎない
- 予測の遠さ（日）ごとのモデル（1 位の一部、5 位は 42 個、16 位は 39 個）
- 直近 14・28・56 日の窓の統計量、指数加重平均、ばらつき、ジャンル別の統計量
- 外れ値（年末年始など）を上限で抑え、学習行から除く（8 位）
- 天気の外部データ（8 位）
- LightGBM・XGBoost・NN のアンサンブル（1 位）

## 既知の問題・未検証の事項

- test は全店舗 × 全 39 日で、定休日らしい日も含む。Data ページの説明では休業日は採点されず、train に記録の無い日は休業日なので、CV の評価行と採点される行は同じ定義（営業した日）になる。ただし「記録が無い = 休業」が成り立たない日（営業したのに記録が欠けた日）があれば、CV はその日の性能を推定できない（README の P2）
- 検証窓に GW を含むものが無い。1 年前の GW を含む窓での検証は試していない（その時期に記録のある test の店舗は 311 / 821）
- 学習し直しの効果（-0.038）の内訳を、疑似テストで切り分けていない（#019 の `refit_check.py` に相当するもの）
- 学習行の疑似の「何日先か」（`features.pseudo_ahead`）は、学習行の並びと件数から乱数で決まる。分割や学習行の絞り込みを変えると、同じ店舗・日付でも日数が変わる（今回の比較はすべて同じ分割なので影響しない）。(店舗, 日付, seed) から決める方式は未実装
- E09 の改善が、特徴の曜日の置き換えと、統計量の曜日の置き換えのどちらによるかは切り分けていない
- seed を変えた再実行はしていない。小さい差は店舗単位の bootstrap で確かめたが、同じ日の店舗間の相関は考慮していない

## 次のコンペに持ち越すこと

- 予約や販促予定のように「時点によって見え方が変わる入力」は、学習行にも予測時と同じ打ち切りを入れる。ラベル由来の統計量は、学習行では直前まで使う（2 コンペで同じ向き）
- 時系列の提出は、分割平均ではなく全行で学習し直す（2 コンペで同じ向き。差の大きさはデータによって 1 桁違う）
- 少数の特殊な日（祝日）は、多数ある普通の日（土曜）に対応付けると、少ない例からでも学べる
