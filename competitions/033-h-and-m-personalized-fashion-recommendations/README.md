# #033 H&M Personalized Fashion Recommendations

- URL: https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations

- 今回の比較実験テーマ: 二段階推薦・候補生成と MAP@12
- 深さ: Standard

## コンペ概要

過去2年の購入履歴から、顧客ごとに翌7日間に買う商品を最大12件推薦する。

## 基本情報（P0）

- 評価指標は MAP@12。期間内に購入した顧客だけが採点され、購入履歴のない顧客も含む。全顧客について12件を出す。 [公式概要](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/overview)
- 提出は `customer_id,prediction` の CSV。Late Submission は可能。
- 公式データのうち画像を除く CSV 4本を取得した。取引は 31,788,324 行（2018-09-20〜2020-09-22）、顧客 1,371,980、商品 105,542。取引表に欠損はない。
- 2026-11-26 に公式サンプルをそのまま Late Submission し、Public 0.00304 / Private 0.00286 で採点された。選定候補には入れない。

## 上位解法

P4 の記録を commit してから読んだ。いずれも本人の writeup。

- 1位は、多様な検索で1人100件の候補を作り、相互作用の特徴と GBDT で順位付けした。教師は6週、負例は週100万件程度に間引いた。画像と文章の特徴は効かなかったという。 [1位](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/writeups/senkin13-30crmnsia-1st-place-solution)
- 3位は、候補源ごとの順位を特徴にして候補を数十件から数百件に増やした。週ごとに学習した BPR 行列分解の類似度も加えた。 [3位](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/writeups/sirius-3rd-place-solution)
- 8位は、過去の購入・同じ product_code・顧客ベースの協調フィルタ・属性別の人気を候補源に、LGBMRanker を3週の教師で学習した。 [8位](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/writeups/kazuki-8th-place-solution)

1位が公開した候補100件の命中数は、開始日 09-02 / 09-09 / 09-16 で 41,019 / 38,427 / 39,142。E04 の候補100件は 30,989 / 28,216 / 30,212（Recall × 購入ペア数）で、候補の差が大きい。P6 では候補側の着眼点を選び、教師の週数・間引き・行列分解は扱わない。

## 検証設計

- `weekly-v1`。末尾の連続する7日×3窓（開始日は 2020-09-02、09-09、09-16）。評価単位は（窓, 窓内に購入した顧客）で、主指標は全単位をまとめた MAP@12。
- 各窓の予測は、窓の開始日より前の取引だけで行う。入口の `recommend` で取引表を物理的に切り落としてから候補・特徴・教師を作る。再ランキングの教師は窓の直前の週（E05 は直前4週）の購入で、各教師週の候補と特徴もその週の開始日より前の取引から作る。ラウンド数は200に固定し、検証窓は学習の打ち切りに使わない。
- 締切以降の取引を差し替えても予測・候補・特徴が変わらないことをテストする。締切の条件を1日緩めるとテストが落ちることも確かめた。
- 候補は締切前の直近7日または28日に売れた商品だけ。初めて売れた商品（購入ペアの 2.5〜5.4%）は拾えない。
- `customers.csv` は取得時点のスナップショットなので、会員状態・通知設定などの列は使わず、年齢だけを使う。年齢も取得時点の値であり、窓ごとの値との差は確認できない。
- 候補の品質は、候補100件の Recall と、候補内の正解を先頭に並べた場合の MAP@12 で測る。
- [選定計画](selection-p4.json) の候補順は E00〜E05。実質同点の許容差は MAP@12 で 0.0001。実測前に決めた値で、単純な構成を優先する。P6 の後は、P4 の勝者の再実行と P6 の候補だけで選定計画を作り直す。
