# #060 State Farm Distracted Driver Detection

- URL: https://www.kaggle.com/competitions/state-farm-distracted-driver-detection
- カテゴリ: E / 難度: 3 / 計算負荷: M
- 今回の比較実験テーマ: 運転手単位GroupCVと見かけの高精度
- 深さ: Standard
- この題で確かめること: 新しい原理は「グループ（運転手）単位の分割と、画像単位のランダム分割の差」。K002（logloss の較正は提出と同じ形で決める）・K001（分割平均か、全行で学習し直すか）を、NN の出力という別条件で再確認する。初の深層学習コンペなので、torch の環境（`vision` グループ）と学習の基盤も整える

## コンペ概要

**車内カメラの画像から、運転手がどの行動（安全運転・携帯電話・飲食・後ろを向くなど 10 種）をしているかを分類するコンペ。**

- 分野: 画像（多クラス分類）
- 主催: State Farm（米国の保険会社）
- 背景（なぜこの予測が必要か）: 脇見運転を画像から自動で検出できれば、事故の削減や保険の判断に使える
- 予測するもの: test 画像ごとの 10 クラスの確率（c0 安全運転、c1 右手で携帯操作、c2 右手で通話、c3 左手で携帯操作、c4 左手で通話、c5 オーディオ操作、c6 飲食、c7 後ろに手を伸ばす、c8 髪・化粧、c9 同乗者と話す）
- 入力: 640x480 の JPEG（学習 22,424 枚、test 79,726 枚）。学習画像には運転手 ID（`driver_imgs_list.csv`）が付く
- 開催期間・参加チーム数: 2016 年 4 月〜8 月 1 日（Leaderboard の最終提出日時の範囲）。`kaggle competitions leaderboard --download` で取得した Public Leaderboard は 1,439 行（2026-11-17 取得）
- 参考スコア（Public Leaderboard）: 1 位 0.08689、上位 10% 0.24823、中央値 1.50737

出典について: 主催者・背景・クラスの意味は Kaggle Overview / Data の説明を記憶に基づいて要約したもの（クラスの意味は P1 で画像を見て確かめる）。期間・行数・スコアは取得した Public Leaderboard から確認した。

## 基本情報（P0 で記入）

- 評価指標: multi-class logloss（小さいほど良い）。確率は [1e-15, 1-1e-15] に切られ、行の和で割り直される（Evaluation ページの記憶に基づく。`models.logloss` も同じ処理）
- 提出形式（File / Code / 推論API）: File。`img` + `c0`〜`c9` の確率の CSV（79,726 行）
- Late Submission 可否: 可（2026-11-17 に「学習データのクラス比を全画像に出す」ダミーを提出し、Public 2.30198 / Private 2.29969 が返ることを確認。Public 1,210 / 1,439 位相当）
- 提出: `dev submit 60 <ファイル> -m <メッセージ>`、履歴とスコアは `dev submissions 60`
- データ概要（実測）:
  - `driver_imgs_list.csv`: 学習画像 22,424 枚 × (運転手, クラス, ファイル名)。運転手 26 人
  - `imgs/train/c0〜c9/`、`imgs/test/`（79,726 枚）。すべて 640x480
  - test 画像には運転手の情報が無い。test の運転手が学習と別人だという点は、Data ページの説明（記憶）と、P1 の画像の近さ（下記）から判断した

## EDA（P1）

先に `src/cache.py` で縮小キャッシュ（320x240 の JPEG）と小画像（32x24 のグレースケール）を作り、`uv run python competitions/060-state-farm-distracted-driver-detection/src/eda.py` で再現する。

### データの基本

- 運転手 26 人。1 人あたり 346〜1,237 枚（中央値 823）
- 26 人全員が 10 クラスすべてを撮っている。運転手 × クラスの枚数は 2〜182（中央値 82）
- クラスの割合は 0.085（c8）〜 0.111（c0）でほぼ均等。クラス比だけの logloss は 2.2998（ダミー提出の Private 2.29969 とほぼ同じ）

### 似た画像（小画像の相関による最近傍）

画像ごとに平均 0・ノルム 1 にした 32x24 の小画像で、相関が最大の画像を探した。

| 対象 | 最近傍が同じ運転手 | 最近傍が同じクラス（= 1-NN の正解率） | 相関の中央値 |
|---|---:|---:|---:|
| 学習画像 → 自分以外の学習画像 | 1.000 | 0.995 | 0.995 |
| 運転手単位の分割: 検証 → 学習 fold | 0.000 | 0.405 | 0.896 |
| 画像単位のランダム分割: 検証 → 学習 fold | 1.000 | 0.994 | 0.994 |
| test → 学習画像 | — | — | 0.885 |
| test（先頭 5,000 枚）→ 自分以外の test | — | — | 0.990 |

- 学習画像は動画のコマで、同じ運転手・同じクラスにほぼ同じ画像がある。**ランダム分割なら、32x24 の小画像の 1-NN だけで正解率 99.4%**。運転手単位の分割では 40.5%
- test から学習への近さ（0.885）は、運転手単位の分割の検証（0.896）に近く、ランダム分割（0.994）とは大きく違う。test の運転手は学習と別人と考えてよい
- test の中にはほぼ同じ画像がある（0.990）。test 自身が同じ運転手のコマの集まり（上位解法がこれを使ったかは P5 で調べる）

## 検証分割（P2）

### リーク経路

| 経路 | 対策 |
|---|---|
| 同じ運転手のほぼ同じコマが、学習と検証に分かれる | 主評価は運転手単位の分割（`StratifiedGroupKFold`）。`cv.check_driver_disjoint` で全 fold を検査する。ランダム分割との差は H1 で測る |
| 前処理の統計量 | 画像の正規化は backbone の ImageNet の固定値（timm の設定）。ロジスティック回帰の標準化は学習 fold の平均・標準偏差だけから作る |
| epoch 数・温度などを検証 fold で選ぶ楽観 | epoch 数は固定（early stopping しない）。検証の損失は epoch ごとに記録するが選択には使わない。温度は P7 で入れ子にして決める（K002） |
| 凍結特徴の作成 | 画像だけから決まり、ラベルを使わない。全画像で一度作って保存する |

### 分割

- **主評価 `driver-sgkf5-seed42-v1`**: 運転手単位の 5 fold（クラス比をそろえる `StratifiedGroupKFold`、seed 42）。各 fold の検証は 5〜6 人・4,267〜4,710 枚。学習と検証で運転手が重ならない
- 比較用 `image-skf5-seed42-v1`: 同じ全行を画像単位の層化 5 fold に分ける。どの fold も 26 人全員が学習と検証の両方にいる

## Baseline（P3）

`uv run python competitions/060-state-farm-distracted-driver-detection/src/train.py <run_id...>` で実行する。

- 構成: 実験定義は `src/train.py`、CV と保存は `src/pipeline.py`、モデルは `src/models.py`（timm の学習済み backbone）
- 固定したもの: seed 42、上記の分割、指標は multi-class logloss（`models.logloss`）。入力は縮小キャッシュの 240x320（縦横比を保つ）
- E00: 学習 fold のクラス比
- E01: 凍結した ResNet50（`resnet50.a1_in1k`）の pooled 特徴（2,048 次元）+ ロジスティック回帰（学習 fold で標準化、C=0.1）
- E02: 同じ ResNet50 の全層 fine-tune。AdamW（lr 3e-4、weight decay 0.05）、1 epoch の warmup + cosine、5 epoch、batch 64、bf16。augmentation は弱め（拡大切り出し 0.75〜1.0、回転 ±10°、明るさ・コントラスト・彩度 ±0.2）、左右反転なし
- テスト予測は 5 つの fold のモデルの平均

## 仮説

予想は実験の前に書いた（2026-11-17、E01 の実行中・結果を見る前）。

| # | 仮説 | 根拠（EDA） | 出所 | 予想 | 結果 |
|---|---|---|---|---|---|
| H1 | 画像単位のランダム分割は、同じ行を評価しても運転手単位の分割より大きく楽観的。モデルの採否も変わる | ランダム分割なら小画像の 1-NN で 99.4%、運転手単位で 40.5% | 自力（新しい原理） | E02 のランダム分割（E02R）は logloss 0.05 未満、運転手単位の E02 は 0.3〜0.8。augmentation の有無（H3）の採否は、ランダム分割では逆になるか差が消える | |
| H2 | ImageNet 学習済みの ResNet50 を全層 fine-tune すると、凍結特徴 + ロジスティック回帰より大きく良い | 運転手単位では似た画像に頼れない。姿勢・手の位置の細かい違いを捉える必要がある | 自力 | E01 は 0.8〜1.3、E02 は 0.3〜0.8（半分以下） | |
| H3 | 弱い augmentation は効く（外すと悪化）。左右反転を足すと悪化する | 学習は 26 人だけ。c1/c3（右手・左手で携帯操作）と c2/c4（同、通話）は反転で入れ替わる | 自力 | augmentation なし（E03）は E02 より 0.05 以上悪化。反転あり（E04）も 0.05 以上悪化し、c1/c3・c2/c4 の取り違えが増える | |
| H4 | 温度スケーリングで logloss が改善する。ただし提出と同じ形（fold 平均か学習し直しか）の予測で決めないと効果が変わる | NN の確率は過信になりやすく、logloss は自信のある誤りに厳しい | 自力（K002 の再確認） | P7 で確かめる。単一モデルの OOF で決めた温度は 1 より大きく、fold 平均の予測では効果が小さい | |
| H5 | 提出は、fold 平均と全行で学習し直した 1 モデルとで差が出る | — | 自力（K001 の再確認） | P7 で確かめる。NN は seed・fold ごとのばらつきが大きく、平均の方が良い | |
