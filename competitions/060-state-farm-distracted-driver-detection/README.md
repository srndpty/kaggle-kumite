# #060 State Farm Distracted Driver Detection

- URL: https://www.kaggle.com/competitions/state-farm-distracted-driver-detection
- カテゴリ: E / 難度: 3 / 計算負荷: M
- 今回の比較実験テーマ: 運転手単位GroupCVと見かけの高精度
- 深さ: Standard
- この題で確かめること: 新しい原理は「グループ（運転手）単位の分割と、画像単位のランダム分割の差」。K002（logloss の較正は提出と同じ形で決める）・K001（分割平均か、全行で学習し直すか）を、NN の出力という別条件で再確認する。初の深層学習コンペなので、torch の環境（`vision` グループ）と学習の基盤も整える

## コンペ概要

**車内カメラの画像から、運転手がどの行動（安全運転・携帯電話・飲食・後ろを向くなど 10 種）をしているかを分類するコンペ。**

- 分野: 画像（多クラス分類）
- 主催: State Farm（米国の保険会社）
- 背景（なぜこの予測が必要か）: 脇見運転を画像から自動で検出できれば、事故の削減や保険の判断に使える
- 予測するもの: test 画像ごとの 10 クラスの確率（c0 安全運転、c1 右手で携帯操作、c2 右手で通話、c3 左手で携帯操作、c4 左手で通話、c5 オーディオ操作、c6 飲食、c7 後ろに手を伸ばす、c8 髪・化粧、c9 同乗者と話す）
- 入力: 640x480 の JPEG（学習 22,424 枚、test 79,726 枚）。学習画像には運転手 ID（`driver_imgs_list.csv`）が付く
- 開催期間・参加チーム数: 2016 年 4 月〜8 月 1 日（Leaderboard の最終提出日時の範囲）。`kaggle competitions leaderboard --download` で取得した Public Leaderboard は 1,439 行（2026-11-17 取得）
- 参考スコア（Public Leaderboard）: 1 位 0.08689、上位 10% 0.24823、中央値 1.50737

出典について: 主催者・背景・クラスの意味は Kaggle Overview / Data の説明を記憶に基づいて要約したもの（クラスの意味は P1 で画像を見て確かめる）。期間・行数・スコアは取得した Public Leaderboard から確認した。

## EDA（P1）

先に `src/cache.py` で縮小キャッシュ（320x240 の JPEG）と小画像（32x24 のグレースケール）を作り、`uv run python competitions/060-state-farm-distracted-driver-detection/src/eda.py` で再現する。

### データの基本

- 運転手 26 人。1 人あたり 346〜1,237 枚（中央値 823）
- 26 人全員が 10 クラスすべてを撮っている。運転手 × クラスの枚数は 2〜182（中央値 82）
- クラスの割合は 0.085（c8）〜 0.111（c0）でほぼ均等。クラス比だけの logloss は 2.2998（ダミー提出の Private 2.29969 とほぼ同じ）

### 似た画像（小画像の相関による最近傍）

画像ごとに平均 0・ノルム 1 にした 32x24 の小画像で、相関が最大の画像を探した。

| 対象 | 最近傍が同じ運転手 | 最近傍が同じクラス（= 1-NN の正解率） | 相関の中央値 |
|---|---:|---:|---:|
| 学習画像 → 自分以外の学習画像 | 1.000 | 0.995 | 0.995 |
| 運転手単位の分割: 検証 → 学習 fold | 0.000 | 0.405 | 0.896 |
| 画像単位のランダム分割: 検証 → 学習 fold | 1.000 | 0.994 | 0.994 |
| test → 学習画像 | — | — | 0.885 |
| test（先頭 5,000 枚）→ 自分以外の test | — | — | 0.990 |

- 学習画像は動画のコマで、同じ運転手・同じクラスにほぼ同じ画像がある。**ランダム分割なら、32x24 の小画像の 1-NN だけで正解率 99.4%**。運転手単位の分割では 40.5%
- test から学習への近さ（0.885）は、運転手単位の分割の検証（0.896）に近く、ランダム分割（0.994）とは大きく違う。test の運転手は学習と別人と考えてよい
- test の中にはほぼ同じ画像がある（0.990）。test 自身が同じ運転手のコマの集まり（上位解法がこれを使ったかは P5 で調べる）

## 検証分割（P2）

### リーク経路

| 経路 | 対策 |
|---|---|
| 同じ運転手のほぼ同じコマが、学習と検証に分かれる | 主評価は運転手単位の分割（`StratifiedGroupKFold`）。`cv.check_driver_disjoint` で全 fold を検査する。ランダム分割との差は H1 で測る |
| 前処理の統計量 | 画像の正規化は backbone の ImageNet の固定値（timm の設定）。ロジスティック回帰の標準化は学習 fold の平均・標準偏差だけから作る |
| epoch 数・温度などを検証 fold で選ぶ楽観 | epoch 数は固定（early stopping しない）。検証の損失は epoch ごとに記録するが選択には使わない。温度は P7 で入れ子にして決める（K002） |
| 凍結特徴の作成 | 画像だけから決まり、ラベルを使わない。全画像で一度作って保存する |

### 分割

- **主評価 `driver-sgkf5-seed42-v1`**: 運転手単位の 5 fold（クラス比をそろえる `StratifiedGroupKFold`、seed 42）。各 fold の検証は 5〜6 人・4,267〜4,710 枚。学習と検証で運転手が重ならない
- 比較用 `image-skf5-seed42-v1`: 同じ全行を画像単位の層化 5 fold に分ける。どの fold も 26 人全員が学習と検証の両方にいる

## Baseline（P3）

`uv run python competitions/060-state-farm-distracted-driver-detection/src/train.py <run_id...>` で実行する。

- 構成: 実験定義は `src/train.py`、CV と保存は `src/pipeline.py`、モデルは `src/models.py`（timm の学習済み backbone）
- 固定したもの: seed 42、上記の分割、指標は multi-class logloss（`models.logloss`）。入力は縮小キャッシュの 240x320（縦横比を保つ）
- E00: 学習 fold のクラス比
- E01: 凍結した ResNet50（`resnet50.a1_in1k`）の pooled 特徴（2,048 次元）+ ロジスティック回帰（学習 fold で標準化、C=0.1）
- E02: 同じ ResNet50 の全層 fine-tune。AdamW（lr 3e-4、weight decay 0.05）、1 epoch の warmup + cosine、5 epoch、batch 64、bf16。augmentation は弱め（拡大切り出し 0.75〜1.0、回転 ±10°、明るさ・コントラスト・彩度 ±0.2）、左右反転なし
- テスト予測は 5 つの fold のモデルの平均

## 仮説検証（P4）

比較は `dev compare 60 <基準> <run_id...>`（同じ分割どうし）と `src/analyze.py compare`（運転手単位の bootstrap。分割の違う run は `--cross-split`）で行う。
`src/leak_check.py` で、運転手単位の分割は全 fold で運転手が重ならないこと（ランダム分割では重なること）と、分割 0 の検証ラベルを変えても E01 の検証・test の予測が変わらないことを確認した。fine-tune は検証ラベルを引数に取らない。

### seed の揺らぎ（判断の基準）

- E02 を seed 42・1・2 で 3 回: OOF 0.38614 / 0.38039 / 0.38549（幅 0.006）。全体の値は安定している
- 一方で fold・運転手ごとには大きく揺れる。fold 3 は 0.518 / 0.455 / 0.494。seed 違いどうしの運転手単位 bootstrap の区間は ±0.06〜0.07 と広い
- epoch ごとの検証 logloss も単調ではない（例: E02 fold 3 は epoch 4 → 5 で 0.405 → 0.518）。運転手の少ない検証では、1 run の fold の値で epoch や設定を選ぶのは危険
- 判断: 全体の OOF の差が 0.01 未満なら揺らぎの範囲とみなす。0.04〜0.06 の差は、seed 3 本のどれより悪いかどうかも合わせて見る

### H1: ランダム分割の楽観と採否の逆転（新しい原理）

| モデル | 運転手単位 | ランダム分割 | 比 |
|---|---:|---:|---:|
| E01 凍結特徴 + LR | 1.07919 | 0.03548 | 30 倍 |
| E02 fine-tune | 0.38614 | 0.02047 | 19 倍 |
| E03 augmentation なし | 0.44258 | 0.01670 | 27 倍 |

- 楽観は予想どおり 1 桁以上。凍結特徴 + LR でさえランダム分割では 0.035 になる（EDA の 1-NN 99.4% と同じく、同じ運転手のほぼ同じコマを覚えれば当たる）
- **採否が逆転した**: augmentation を外すと、運転手単位では +0.056 悪化、ランダム分割では -0.0038 改善（区間が 0 をまたがず、18/26 人で改善）。ランダム分割で選ぶと augmentation を捨てることになる
- E02 の Public 0.34084 / Private 0.26757 は運転手単位の OOF（0.386）に近く、ランダム分割の 0.020 とは 1 桁違う（Late は 5 fold の平均なので OOF よりやや良い）

### H2: fine-tune と凍結特徴

- E01 1.079 → E02 0.386。予想の範囲（E01 0.8〜1.3、E02 0.3〜0.8）に入った
- 凍結特徴は fold ごとの差が大きい（0.856〜1.426）。ImageNet の特徴は姿勢・手の位置より背景や人物の見た目を拾い、知らない運転手で崩れると考えられる（未検証）

### H3: augmentation と左右反転

- augmentation なし（E03）は +0.056、反転あり（E04）は +0.042 悪化。どちらも seed 3 本のどれより悪いが、運転手単位の区間は 0 をまたぐ（26 人しかない）。方向は支持、強さは中程度
- E03 は学習損失が 0.0013 まで下がる（E02 は 0.008）。学習画像を覚えるほど、知らない運転手では悪化する
- 反転の予想（c1/c3・c2/c4 の取り違えが増える）は外れた。c1→c3 は 3 → 18 枚、c2→c4 は 26 → 24 枚。反転すると車内（ハンドルや窓の位置）も反転するので、モデルは区別できると考えられる。悪化は c4・c7 などの c8 への取り違え（c4→c8 90 → 136 枚）

### エラー分析（E02）

- 正解率 0.890。損失はクラス c9（同乗者と話す、1.208）・c0（安全運転、0.862）・c8（髪・化粧、0.617）に集中。c9↔c0 の取り違えが 515 + 354 枚で最多。どちらも両手がハンドルにあり、顔の向きだけが違う
- 運転手 p072（346 枚）は logloss 2.367・正解率 0.471 で突出。2 番目の p081 は 0.836
- 損失の大きい上位 5% の行が損失の 61.5% を占める（自信のある誤り）。温度スケーリング（H4）の余地がある

## 上位解法の再現（P6）

### 事前に決めたこと（実行前に記入）

- P6 は「近傍の予測の平均」を再現する（1 位・3 位に共通し、学習し直さずに E02 の予測に足せる）。切り出しは検出器の学習が要るので Standard の範囲では行わない
- CV での再現: 近傍は **同じ fold の検証画像の中だけ** で探す（test では test の中だけで探すのと同じ形）。画像だけから決まり、ラベルを使わない。検証は 5〜6 人で、運転手 1 人あたりの枚数は test と同程度（test は 79,726 枚）
- E05: 32x24 の小画像の相関で近傍 10 枚を選び、自分を含む 11 枚の予測を単純平均する（EDA で同じ運転手の中の最近傍が 99.5% 同じクラスだったため）。k=10 は 1 位の値で、調整しない
- E05F: 近傍を、凍結 ResNet50 の pooled 特徴（E01 と同じ）で選ぶ（1 位は VGG16 の pool5）
- 予想: E05 は E02 の 0.386 から 0.1 以上改善する（1 位の約 0.10〜0.12）。E05F は E05 と差が小さい
- **最終モデルの選び方**（P6 の結果を見る前に決めた）: E02 の構成に、OOF が 0.02 以上改善し（seed の揺らぎ 0.006 の 3 倍）、改善した運転手が 26 人中 18 人以上の後処理だけを足す。E05 と E05F が両方とも条件を満たすときは OOF の良い方を採る（2 候補からの選択なので、楽観は小さいとみなす）。温度（H4）は採用した予測に対して P7 で入れ子にして決める。提出は fold 平均（H5 の学習し直しは比較用に Late で測るだけで、選択には使わない）。Private は選択に使わない

## 最終評価（P7）

### 事前に決めたこと（実行前に記入）

- 最終モデル（P6 の規則による）: **E05F**（E02 の 5 fold 平均 + 凍結 ResNet50 の特徴で選んだ近傍 10 枚の平均）

- 温度の採否: 疑似テストで「平均 + 近傍」→「平均 + 近傍 + T」が改善し、運転手単位 bootstrap の改善の割合が 0.95 以上なら、E05F の OOF（単一 + 近傍の形）で決めた T を提出にかける。そうでなければかけない
