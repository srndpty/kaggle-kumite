# #060 State Farm Distracted Driver Detection 振り返り

車内カメラの画像から、運転手の行動（安全運転・携帯電話・飲食など 10 クラス）を分類する（評価は multi-class logloss）。学習は 26 人の運転手の動画のコマ 22,424 枚で、test（79,726 枚）の運転手は学習と別人。初めての画像・深層学習のコンペ。詳細な数値と手順は [README.md](README.md) を参照。

## 自力の仮説で効いたこと・効かなかったこと

- **運転手単位の分割が必須（H1、今回のテーマ）**: 画像単位のランダム分割は、同じ行の評価で 19〜30 倍楽観的（fine-tune で 0.386 と 0.020）。32x24 の小画像の 1-NN だけでランダム分割の正解率が 99.4% になる（運転手単位では 40.5%）
  - **採否も逆転した**: augmentation を外すと、運転手単位では +0.056 悪化、ランダム分割では -0.0038 改善（区間が 0 をまたがない）。ランダム分割で選ぶと、知らない運転手への汎化に効く augmentation を捨ててしまう
  - Late は運転手単位の値に近い（E02 は Public 0.341）
- **fine-tune は凍結特徴より大幅に良い（H2）**: 1.079 → 0.386。凍結特徴の LR は fold ごとの差も大きい（0.86〜1.43）
- **弱い augmentation（H3）**: 外すと +0.056、左右反転を足すと +0.042。どちらも seed 3 本のどれより悪いが、26 人の bootstrap 区間は 0 をまたぐ。反転で右手・左手のクラスの取り違えが増えるという予想は外れた（c1→c3 は 3 → 18 枚）。車内も一緒に反転するので区別できると考えられる
- **seed の揺らぎ**: 全体の OOF は 0.380〜0.386 と安定しているが、fold・運転手ごとの値は大きく揺れる（seed 違いどうしの bootstrap 区間が ±0.06）。epoch ごとの検証の損失も単調ではなく、少数の運転手の検証で epoch を選ぶのは危険

## 上位解法から学び、再現したこと

出典: 本人の writeup は Kaggle の Discussion が取得できず読めていない。1 位・3 位・5 位は第三者の GitHub の README による要約（本人の投稿へのリンク付き）と、参加者のブログ。10 位は本人の公開コードと解法図。

- **test の中の似た画像との予測の平均（1 位が直接の先行例。3 位は近傍の画像を合成した入力で予測する別方式、E05F）**: test は同じ運転手の動画のコマの集まりなので、近傍（同じ場面）の予測を平均すると、単発の自信のある誤りが均される。CV では、近傍を同じ fold の検証画像の中だけで探して再現した（ラベルを使わない。test で test の中だけを探すのと同じ形）
  - OOF -0.114（26/26 人で改善）、Late は Private -0.050、Public -0.060
  - 近傍は画素の小画像より、凍結 ResNet50 の特徴で選ぶ方が良い（-0.012）
  - **CV は提出での効果を 2 倍に見積もった**: OOF は単一モデルの形で、単一には -0.124 効くが、提出と同じ平均の形では -0.053 にとどまる（疑似テスト）。平均も近傍も揺れを均すので、効果が重なる。ただし疑似テストの各モデルは 60% で学習し（E02 は 80%）、近傍を探す集合の大きさも test と違うので、差のすべてが平均によるとは示していない
- 平均の効果と温度（P7、K001・K002 の再確認）:
  - 全行で学習し直した 1 モデル（E07）は、fold 平均より Private +0.073 悪い。NN は 1 本ごとの揺れが大きく、平均の効果（疑似テストで -0.133）が学習量の差（80% と 100%）より大きい
  - 単一モデルの OOF で決めた温度（約 1.35）は、単一には効く（-0.034）が、平均には逆効果（+0.028）。提出には温度をかけなかった

## 上位解法との差分（試さなかった着眼点）

- 運転手に注目する切り出し: 1 位は頭部・手（ラジオ周り）を切り出した 3 入力、10 位は体の領域を検出して切り出す。損失の大半は c9（同乗者と話す）と c0（安全運転）の取り違えで、違いは顔の向きだけなので、頭部の切り出しは効く可能性が高い（未検証）
- 1 位の「まとまりで予測を共有する」処理、クラスごとのモデル選択
- 3 位の、近傍の画像を合成した test 画像での予測
- 5 位の、学習画像の左右の半分を組み合わせた合成画像（約 500 万枚）
- 大きいモデル・高解像度・長い学習・TTA・複数モデルのアンサンブル。今回は ResNet50、240x320、5 epoch の 1 構成のみ
- 疑似ラベル（test を学習に使う）

## 既知の問題・未検証の事項

- H3 の効果（+0.04〜0.06）は 26 人の bootstrap では 0 をまたぐ。seed を増やした比較はしていない
- 近傍の k（10）と重みは 1 位の値のまま調整していない。近傍で同じ運転手のコマを拾えているかの検査（学習データでの同じ運転手の割合）はしていない
- E05F が E05 より良い理由（特徴の頑健さ）は推測
- Public と Private の差（約 0.06）の原因
- 運転手 p072 だけが極端に悪い（E02 で logloss 2.37）理由は見ていない
- bf16 の GPU 推論は再実行で揺らぐ。凍結特徴を作り直すと最大で相対 1.2% 変わり、E05F の OOF は 0.27237 → 0.27247 になる（結論は変わらない）
- E00〜E07F は画像キャッシュの manifest（レビュー後に導入）より前に作ったので、run の記録だけでは使った配列を特定できない。キャッシュは標本の照合で元画像との一致を確かめた。後処理の元にすることも、`nested.py report` で P7 の診断を再計算することも拒否する（旧 run の予測と作り直した特徴が混ざるため）。P7 の数値は記録を正とする

## 次のコンペに持ち越すこと

- グループ（人・動画・患者など）があるデータでは、まずグループ単位とランダムの 1-NN の正解率を比べる。差が大きければグループ単位の分割が必須で、ランダム分割では採否まで変わる
- 後処理（温度・近傍の平均）は、提出と同じ形（fold 平均）の予測で効果を測る。入れ子の疑似テストは、NN でも 20 本の学習（約 75 分）で作れた
- NN の提出は fold 平均を基本にする（学習し直しの 1 本は大きく悪い）
- 画像の基盤: 縮小画像をデコード済みの uint8 配列（memmap）にし、augmentation を GPU 上で行うと、DataLoader の律速が消えた（1 epoch 114 秒 → 27 秒）
- 派生キャッシュ（配列・小画像・CNN 特徴）は作るときに manifest（作り方・元の行順・内容ハッシュ・重みのハッシュ）を書き、使うときに照合して、run に manifest のハッシュを記録する。後処理の run は元の run とデータ・分割・キャッシュが一致することを確かめる（`src/integrity.py`。2 つ目の画像コンペで `kumite` に移す）
- 追加・更新した知見カード: K011（新規、グループ単位の分割とランダム分割）、K012（新規、test の中の近傍の予測の平均）、K001・K002（証跡を追加）
