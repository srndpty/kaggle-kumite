# #090 Detect Sleep States 振り返り

系列を分けた3-foldで、加速度系列の1分ごとのスコアから入眠・起床イベントを検出した。ベースラインの OOF Event Detection AP は **0.052515**。現地時刻を1日周期で符号化した **E04（0.102437）** を、Late Submission の結果を見る前に最終構成として固定した。 [検証設計](README.md) [選定記録](selection.json) [実験ログ](experiments.jsonl)

## 比較実験

| Run | 変更 | OOF AP | 入眠 AP | 起床 AP |
|---|---|---:|---:|---:|
| E00 | 前後5分の統計量 | 0.052515 | 0.049887 | 0.055143 |
| E01 | 前後30分の統計量を追加 | 0.096479 | 0.104703 | 0.088256 |
| E02 | 正例を前後3分に拡張 | 0.095724 | 0.074686 | 0.116763 |
| E03 | 重複抑制を15分から60分に拡張 | 0.041445 | 0.039926 | 0.042964 |
| E04 | 現地時刻の1日周期を追加 | 0.102437 | 0.090053 | 0.114821 |

入眠・起床の各 AP は10許容幅の平均。各実験は E00 からの単独変更。

- **E01** は入眠 AP の改善が +0.054816 で、起床の +0.033113 より大きかった。1分幅で入眠の検出数は 1,522 → 1,459 に減ったが、AP は 0.007526 → 0.013579 に上昇した。追加した時間文脈は、この設定で高スコア候補の順位改善に寄与した。
- **E02** は30分幅で両イベントの AP を上げた。全候補を含めると E00 も E02 も30分幅で全正解とマッチした。1分幅では両イベントのマッチ件数が減ったが、起床 AP は 0.007875 → 0.016625 に上がった。候補全体の再現率と、信頼度順で加点される AP は異なる挙動を示した。
- **E03** は30分幅で、未マッチだが同種の正解が許容幅内にある重複候補を16,999件から0件に減らした。同じ幅の見逃しは0件から1,233件に増え、AP は全体で −0.011071。信頼度が低い候補も含めた件数では、誤検出が大きく減っても AP の改善につながらなかった。 [K034](../../knowledge/K034-nms-threshold-for-dense-detection.md)

## 上位解法と E04

1位の本人発表は、正解の分単位の偏りと複数の許容幅を踏まえて、イベントの出力位置を設計した。16位の本人 writeup は、系列モデルにスペクトログラム・移動統計・周期時刻を入れ、別モデルの睡眠状態の推定値でイベントを再採点した。 [1位の発表資料](https://speakerdeck.com/unonao/shui-mian-konpe-1st-place-solution) [16位の解法](https://www.kaggle.com/competitions/child-mind-institute-detect-sleep-states/writeups/nikita-babich-16th-place-solution)

E04 は16位の周期時刻の着眼点を、配布時刻の時・分を1日周期の sin・cos に変換する特徴量として再現した。E00 に対して OOF AP は +0.049922。1分幅の入眠・起床 AP は 0.012946 / 0.017112、30分幅では 0.129602 / 0.162247 だった。1分幅の見逃しは入眠 3,303件・起床 3,223件。30分幅では両イベントとも全正解に候補があり、重複は17,210件だった。全候補の誤検出数は減らなかったため、今回観測された効果は AP での順位改善。時間帯別の誤検出の内訳は未集計。

## 分割を変えた確認

最終構成を固定した後、主分割で差が +0.005958 だった E04 と E01 を seed 2026 の新しい系列分割で比較した。E01 は 0.106158、E04 は 0.097233 で順位が逆転した。主分割では E04 の優位が3 fold 中1つだった。周期時刻と長い時間文脈のどちらを選ぶかは、今回の分割に依存した。

## 外部評価

E00 と E04 はともに、3 fold のビンスコアを平均してからピークを抽出する非公開 CPU Notebook で提出した。公開テストの3系列・6候補は、それぞれローカルと Kaggle で ID、step、イベント種別、スコアが一致した。

| Run | Notebook 版 | 提出 ID | Public | Private |
|---|---:|---:|---:|---:|
| E00 | 2 | 58810181 | 形式エラー | 形式エラー |
| E04 | 1 | 58810349 | 形式エラー | 形式エラー |

Kaggle API の一覧では両方とも COMPLETE だったが、提出詳細のスコアは空欄で、CSV の形式エラーが返った。詳細な発生条件は示されなかった。

候補数が形式エラーに関係している可能性を切り分けるため、同じ重み・ピーク抽出に対して、系列の記録日数あたりイベント種別ごとに高スコアから8候補を残した。OOF 候補は E00 の980,369件、E04 の996,058件から、両方120,368件になった。候補制限後の OOF AP は E00 が0.042903、E04 が0.098687。最終構成の選定は維持し、両モデルに同じ制限を加えて再提出した。

| Run | Notebook 版 | 提出 ID | Public | Private |
|---|---:|---:|---:|---:|
| E00-capped | 3 | 58823233 | 0.051 | 0.066 |
| E04-capped | 2 | 58823236 | 0.171 | 0.202 |

候補制限後の E04 は、E00 に対して Public **+0.120**、Private **+0.136**。同じ候補制限での OOF 差 **+0.055784** と方向が一致した。外部評価と OOF では評価対象の系列とスコアの平均方式が異なるため、改善幅の差の要因は分離できない。両方の再提出が採点されたが、初回に形式エラーが起きた正確な条件は未確認。

## 再現性

主分割の5構成は、保存済み OOF を再採点してログと照合した。1分幅の境界ではちょうど12ステップ離れた候補を未マッチとする。公式実装と、合成ケースおよびベースラインの18系列・64,345候補で一致を確認した。公式参照コードの集約処理は pandas 3 のグループキー API に合わせて読み替えた。

比較9 run・90成果物のハッシュを照合した。記録済み実行時間の合計は約8分02秒。

E04 の提出用推論を学習用センサー全277系列に通す負荷確認では、42.3秒、ピークメモリ約14.5 GiBで976,985候補を生成した。この実行では採点していない。
