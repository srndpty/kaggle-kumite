# K008: 検証でも「その時点で分かる情報の範囲」を test と同じにする

- 状態: 再現
- 分類: 検証

## 仮説

未来の予定（祝日・休業・販促など）から作る特徴は、予測期間の末尾より先が見えない。検証窓の行が窓より先の予定まで見ていると、ラベルを使っていなくても検証が test より易しくなり、CV が楽観的になる。

## 観測

- #019 Rossmann: 「次の休業日・祝日までの日数」を、train と test をつないだ暦から作った。test の 93.4% の行で次の祝日が分からない（NaN）のに、手前の学習行では 1.2% だけだった。検証窓の行は、窓より先の予定まで見えていた
- この特徴を入れた E03 は CV 0.106。提出は Public 0.111・Private 0.126（学習し直しの E06）
- 検証窓でも窓の末尾より先を見せないと（E07）、CV は 0.130 に悪化した（+0.0239）
- 分からない日数を上限値で埋めると（E08）、0.104 に戻った（-0.0260）。学習時にほぼ現れない NaN が、「近くにイベントは無い」というよくある値に置き換わる
- ただし Late の改善は小さかった（E06 → E09 で Public -0.0018、Private -0.0013）。打ち切りを再現した CV は、提出用に学習し直したモデルの状況より厳しかった可能性がある（未検証）
- label perturbation test は通る。ラベルのリークではないので、別の確認が必要（特徴ごとに、欠損や上限値の割合を test・検証窓・学習行で比べる）
- 提出の作り方を比べる疑似テスト（K001）でも同じ問題が起きた。当初は暦を打ち切らず、疑似テストの行が test 期間の予定まで見えていた。打ち切ると、E03 の分割ごとのモデルは 0.145・0.179 → 0.188・0.174 と順序まで変わった。情報条件をそろえた E09 では、疑似テストで early stopping した値が CV の分割 2 と一致した（そろえられていることの確認になる）
- ラベルを使う特徴にも、時間の向きの条件がある。店舗別の売上平均を、学習行は「自分の期間以外」（未来の期間を含む）から、検証行は過去だけから作ると（E04）、E02 比 -0.0017。どの行も「その日より前の売上」だけから作ると（E12）-0.0075。外側の検証ラベルは使っていない（label perturbation test は両方とも通る）ので、ラベルのリーク検査では見つからない
  - 予測期間（48 日）ぶん離して、学習行の特徴の新しさを検証行にそろえる（E13）と、E12 より +0.0014 悪い。新しさを完全にそろえるより、直近の水準を使える方が良かった

- #024 Recruit（予約）: test の予約は train の末尾までに入ったものだけ。検証窓の予約人数のうち、窓の開始前に入っていたのは 24.5%（1 週目 58.5%、4 週目以降 3〜6%）
  - 検証行で窓の開始以後の予約まで見せると（E05L）、CV は 0.0049 楽観的になる。label perturbation test とは別に、「窓の開始以後の予約を変えても検証行の入力が変わらない」ことを検査した（打ち切らない E05L だけで変わることも確認）
  - **学習行にも打ち切りを入れる必要があった**: 学習行で来店日までの全予約を使うと（E05A）、予約を使わない場合より悪い（E05 比 +0.0090）。学習行ごとに「何日先か」（0〜38 日）をランダムに割り当て、その日数だけ前の起点より前に入った予約だけを数え、日数も特徴にすると（E05）改善した（E02 比 -0.0034）。一様な割り当てによる近似で、予測時に見える予約の分布をそのまま再現したものではない
  - E05A は「何日先か」の列（学習行はすべて 0）も同時に変えていた。この列だけ E05 に戻した E05B でも E05A と差が無い（+0.0004、[-0.0004, +0.0013]）。悪化は予約の打ち切りの有無による
  - 一方、ラベル由来の統計量に同じ打ち切りを入れると（E08）、+0.0017 悪化した（Late も悪化）。#019 の E13（予測期間ぶん離す）と同じ向き
- #024 では暦（祝日）も検証窓の末尾で打ち切ったが、窓の末尾の翌日しか影響しないので、効果は測っていない
- #021 M5 は28日先を一括予測する。予定価格と暦は対象日まで、売上履歴は予測起点までを参照する。過去の学習例も同じ情報条件で構成し、外側の締切後の売上を改変して売上特徴・予測入力・採点の尺度と重みの不変性を確認した。この分割では情報条件を変える比較は実施していない。

## 適用条件

- 予測期間の入力（予定）から、前後の時点をまたぐ特徴を作る場合
- 特徴は分割ごとに「検証窓の末尾までの情報」で作り直す。疑似テストでは、使う入力のデータそのものを疑似テストの末尾で切り詰める（参照できないようにする）
- ラベルを使う特徴は、学習行も検証行も「その日より前のラベル」だけから作る（expanding window）。cross-fitting で自分の期間を除くだけでは、時間の向きがそろわない。学習行では直前まで使い、予測期間ぶん離したり起点に合わせたりしない（#019・#024 で離すと悪化）
- 時点によって見え方が変わる入力（予約など、後から増える値）は、学習行にも予測時の打ち切りを（行ごとに「何日先か」を割り当てる近似でよいので）入れ、「何日先か」を特徴に加える。打ち切りで値が系統的に小さくなる入力では、学習行を打ち切らないと、入れない場合より悪くなりうる（#024）

## 未検証

- 1 位（#024）のように、起点をずらして行を複製した学習データを作る方法（1 行に 1 起点を割り当てる E05・E08 の近似との比較）
- 打ち切りを入れるべき入力と入れるべきでない入力の境目（予約は入れると改善、ラベル由来の平均は入れると悪化。打ち切りで値が系統的に偏るかどうか、という解釈は未検証）
- 打ち切りを再現した CV と Late の対応が、他のデータでどの程度良いか

## 次の検証機会

- 予定や暦を使う時系列コンペ（#020 Favorita など）。販促予定のように後から確定する入力があれば、学習行の打ち切りの有無を比べる
