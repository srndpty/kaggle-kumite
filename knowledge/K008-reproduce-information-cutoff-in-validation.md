# K008: 検証でも「その時点で分かる情報の範囲」を test と同じにする

- 状態: 仮説
- 分類: 検証

## 仮説

未来の予定（祝日・休業・販促など）から作る特徴は、予測期間の末尾より先が見えない。検証窓の行が窓より先の予定まで見ていると、ラベルを使っていなくても検証が test より易しくなり、CV が楽観的になる。

## 観測

- #019 Rossmann: 「次の休業日・祝日までの日数」を、train と test をつないだ暦から作った。test の 93.4% の行で次の祝日が分からない（NaN）のに、手前の学習行では 1.2% だけだった。検証窓の行は、窓より先の予定まで見えていた
- この特徴を入れた E03 は CV 0.106。提出は Public 0.111・Private 0.126（学習し直しの E06）
- 検証窓でも窓の末尾より先を見せないと（E07）、CV は 0.130 に悪化した（+0.0239）
- 分からない日数を上限値で埋めると（E08）、0.104 に戻った（-0.0260）。学習時にほぼ現れない NaN が、「近くにイベントは無い」というよくある値に置き換わる
- ただし Late の改善は小さかった（E06 → E09 で Public -0.0018、Private -0.0013）。打ち切りを再現した CV は、提出用に学習し直したモデルの状況より厳しかった可能性がある（未検証）
- label perturbation test は通る。ラベルのリークではないので、別の確認が必要（特徴ごとに、欠損や上限値の割合を test・検証窓・学習行で比べる）

## 適用条件

- 予測期間の入力（予定）から、前後の時点をまたぐ特徴を作る場合
- 特徴は分割ごとに「検証窓の末尾までの情報」で作り直す

## 未検証

- 学習行にも同じ打ち切りを人工的に入れる方法（予測の起点を動かして学習データを作る）との比較
- 打ち切りを再現した CV と Late の対応が、他のデータでどの程度良いか
