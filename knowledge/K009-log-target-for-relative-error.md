# K009: 相対誤差の指標では、目的変数を log にして学習する

- 状態: 再現
- 分類: モデル

## 仮説

RMSPE のような相対誤差の指標は、どの行も水準に関係なく同じ重みで見る。目的変数そのままの RMSE は水準の大きい行を重く見るので、log 変換してから RMSE で学習した方が指標に合う。

## 観測

- #019 Rossmann（RMSPE、LightGBM）: 売上そのまま 0.13819 → log1p 0.12907（-0.0093、3/3 分割）。店舗ごとの売上中央値には約 10 倍の幅がある
- #024 Recruit（RMSLE、LightGBM）: 来店数そのまま 0.57940 → log1p 0.54755（-0.0319、3/3 分割）。RMSLE は log1p 空間の RMSE そのものなので、学習の目的と指標が一致する。来店数そのままの LightGBM は、統計的 baseline（店舗 × 曜日の中央値）より悪かった
- log で学習した予測に 1 未満の係数を掛ける後処理（1 位解法が使用）は、係数を外側の各分割の学習期間の中だけで決めると悪化した（E11-r2、+0.0010。決まった係数は 0.979〜0.992 で 1 未満）。全体での最適な係数は 0.995 だが、窓ごとの最適値が 1.009・0.994・0.984 とばらつく

## 適用条件

- 目的変数が正で、行によって水準が大きく違う場合
- 木モデルでも効く。入力の単調変換（K003）と違い、目的変数の変換は損失の重み付けを変える

## 未検証

- 指標そのものを目的関数にする方法（重み 1/y² の二乗誤差など）との比較
- MAPE など他の相対誤差の指標

## 次の検証機会

- 相対誤差や対数誤差を使う回帰コンペ（#011 Allstate の MAE など、指標と log の対応が弱い場合）
