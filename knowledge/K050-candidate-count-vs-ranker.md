# K050: 候補を増やすと上限は上がるが、順位付けが追いつくとは限らない

- 状態: 仮説
- 分類: 推薦 / 評価

## 仮説

候補 Recall と MAP の上限を上げても、順位付けモデルの特徴と学習設定が同じままなら、最終 MAP は上がらないことがある。

## 観測

#033 で、候補を 100 件から人気の下位まで 300 件に広げると、3窓の候補 Recall は 0.130 / 0.124 / 0.141 から 0.242 / 0.233 / 0.251 に、候補内の正解を先頭に並べた MAP の上限は 0.150 / 0.142 / 0.159 から 0.265 / 0.251 / 0.269 に上がった。LambdaRank の OOF MAP@12 は 0.030936 → 0.029114 に下がった（95%区間の差 −0.00209〜−0.00152）。

本人の購入をさかのぼる期間を28日から365日に伸ばすと、Recall は 0.124 / 0.119 / 0.134 に下がったのに、MAP は 0.030936 → 0.033484 に上がった。改善は直近28日に購入のない顧客に集中した。候補100件の枠は一定なので、Recall が人気の候補で稼いだ命中と本人の購入の候補とでは、順位付けしやすさが異なる。

## 適用条件

`weekly-v1` の3窓（7日）、直前1週の教師、ラウンド数200固定の LightGBM LambdaRank。増やした候補は人気の順位だけで決まる商品。Recall と MAP の差は、候補の内訳とあわせて読む。

## 未検証

特徴や学習ラウンド数を候補数に合わせて変えた場合、負例の間引きをした場合、人気以外の検索器で候補を増やした場合。

## 次の検証機会

#040 OTTO で、候補数を変えるときに順位付けの特徴と学習設定も同時に変える場合と変えない場合を比較する。
